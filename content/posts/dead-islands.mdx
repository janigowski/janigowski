Your dead code check says every file is used. It may be wrong.

I ran [Graphify](https://graphify.com) on a large React codebase. It builds a graph of files and imports, and you can ask an LLM questions about it.

I asked for files that nothing imports. It found them. But it also found something I didn't ask for: dead islands.

## A dead island

A dead island is a group of files that import each other, while nothing outside the group imports them. They are never used by the real app.

The smallest one is two files: a component and its test. The test imports the component, so the component looks used. Tools like Knip treat tests and stories as entry points, so they don't report it.

`useElementSize.ts` is 52 lines. The only file that imports it is `useElementSize.test.ts`, 252 lines.

## One example

6 files in 3 folders. A container, the button it renders, two test files and two test mocks. 467 lines, and only 168 of them are product code. Nothing in the app had used it for about a year.

`InvoiceMenu.test.tsx` and `InvoiceMenu.export.test.tsx` import `InvoiceMenu.tsx`, which renders `MenuItem.tsx`. The tests also import two mocks: `csvFile.mock.ts` and `zipFile.mock.ts`.

The island imports 28 files from the app. The app imports none back.

## Why it matters

Software hygiene. Dead files are not free.

Every refactor, codemod, search and AI agent run reads them, and often changes them. You keep maintaining code nobody uses. Fewer files means less to read, for people and for agents.

After building the import graph, ask:

<Callout label="Example insight">

The PR that removed a feature flag left the old code path behind. The fix is in the process: add "remove the dead code" to the feature flag cleanup checklist.
